# Security

Archipel runs code generated by an agent, next to an organisation's data and accounts. This document says what the platform protects against, what it does not do, and how to harden it.

## Reporting a vulnerability

Use GitHub's private reporting, in the repository's **Security** tab, without opening a public issue. Describe the scenario, the version and a way to reproduce it.

## Threat model

| Actor | What they can do | What stops them |
| --- | --- | --- |
| An app's code, including in preview before any decision | Run whatever it wants in its container | Container without network, read-only, unprivileged, with an account without rights and memory, CPU and PID limits. It only talks to the host over stdio, and its tables are limited to those the host grants it. Before approval, its network is limited to the rules already approved for the app, and a physical table held by another app is refused |
| An app's frontend | Run JavaScript in a reviewer's browser | Opaque origin (`sandbox` CSP): no cookie, no access to the platform API, a token limited to the app and tied to the session |
| Agent token | Submit a version, read its reports and the schemas | It never carries `request.user`: every decision is refused to it. It can be limited to chosen apps |
| Visitor not signed in | Call the public routes | Mandatory OIDC, setup code, rate limits, request timeouts |
| Third-party site visited by an administrator | Forge a request with their cookie | `SameSite=Lax`, `Origin` or `Sec-Fetch-Site` compared with the public address, `Host` check |
| Stolen session | Browse as the person | Expiry after 1 h of inactivity and 8 h at most, immediate revocation, and reauthentication within 15 minutes to approve, put back online, uninstall, create a token, add or remove an external link, or change the settings |
| Reading the database | Read its content | Sessions and tokens stored as hashes only |
| Reading `data/instance.json` | Read the configuration | Client secret and database URL encrypted (AES-256-GCM) if `ARCHIPEL_MASTER_KEY` is provided |
| Writing to the database | Rewrite history | Audit log chained by HMAC: `npm run audit-verify` reports a modified or removed line |

## Limits

- **The Docker socket is worth root access.** The host must be able to start containers: whoever compromises it gets this right. Prefer rootless Docker or rootless Podman, and never expose this socket on the network.
- **The container shares the server's kernel.** For outright hostile code, add gVisor with `ARCHIPEL_SANDBOX_RUNTIME=runsc`.
- **The scan helps the reviewer, it is not a barrier.** It spots what an agent writes by mistake. The boundary is the container, and the decision is the review.
- **`npm run dev` does not isolate apps.** They run in a separate process, with Node's permission model, which does not stop malicious code. This mode is refused outside `npm run dev`, and the interface flags it.
- **Reauthentication and `auth_time`.** Archipel asks for `prompt=login` and `max_age=0`, then checks the `auth_time` claim. A provider that does not return this claim cannot prove it asked for the identity again: the sign-in is then accepted as is. Check this on yours.
- **End of the log.** The audit chain detects a change or a removal in the middle, not the deletion of the last lines. Export the log off the server if this matters. A concurrent write from another process (`npm run token` during a submission) can also produce a false alert.
- **Verification after rotation.** A line sealed by a removed key is counted in `unverifiable`, without this being tampering.
- **Static app files.** Non-HTML files are served without a session, since an opaque origin sends no cookie. Put no data in them.
- **External links.** A link's address is visible to everyone signed in: put no secret in it. To fetch the logo, the server calls the host chosen by the administrator, even an internal one, then only public `https` on the standard port. The machine and metadata services stay refused, the response is capped and only an image recognised by its bytes is kept. This logo is served under a `sandbox` CSP.
- **Shell CSP.** `style-src 'unsafe-inline'` is still needed for the styles the interface sets.

## Hardening an instance

1. Serve the platform over https behind a reverse proxy and set `ARCHIPEL_PUBLIC_URL`. Cookies switch to `__Host-`, HSTS turns on, and only this address is accepted.
2. Declare the proxy with `ARCHIPEL_TRUST_PROXY=<addresses>`. Without it, rate limits and the audit see every client under the proxy's address.
3. Provide `ARCHIPEL_MASTER_KEY_FILE`, outside `data/`.
4. Use a rootless container engine, and gVisor for untrusted code.
5. Limit agent tokens to the apps they need, with a short duration.
6. Check that your OIDC provider returns `auth_time`.
7. Back up `data/` and the database, and run `npm run audit-verify` regularly.

## Keys

```bash
openssl rand -hex 32                # ARCHIPEL_MASTER_KEY or ARCHIPEL_SECRET
npm run rotate-secret               # new key, the old one stays accepted
npm run audit-verify                # checks the audit log
```

Each use (sign-in session, app token, audit) has its own key, derived by HKDF. With `ARCHIPEL_SECRET`, rotation is manual: put the old value in `ARCHIPEL_SECRET_PREVIOUS`. Losing `ARCHIPEL_MASTER_KEY` means entering the client secret and the database URL again.
