# Archipel

A self-hosted platform to deploy apps generated by an agent: a shared launchpad, a shared back end, and a human review before anything goes live.

Threat model and hardening: [SECURITY.md](SECURITY.md).

## Getting started

Node 22 or later.

```bash
npm install
npm run build
npm run samples
npm run dev
```

Open http://127.0.0.1:3000. `npm run dev` opens a local session without OIDC, only on a local address.

On first sign-in, a wizard offers to name the platform, configure OIDC and choose the database. Everything can be skipped: nothing is required with `npm run dev`, and everything can still be changed in **Settings**.

In **Apps > Add an app**, drop `samples/dist/customers.tar.gz`, approve it in **Review**, then do the same with `samples/dist/tickets.tar.gz` (it reads the shared table of `customers`, which must therefore be live first).

## Production

Docker or Podman is required: app code only runs in a container, and the server refuses to start without an available engine. Each active app uses 30 to 50 MB, and its first call takes less than a second.

```bash
npm run build
npm start
```

Without a configured OIDC provider, the server starts in setup mode: only `/setup` answers, and a code to enter appears in its logs. It proves that you control the server, which prevents a visitor from taking over an exposed instance.

The wizard has you declare `<public address>/auth/callback` at the provider, then sign in once to check. A provider is only activated after this test, with an account that belongs to the administrator group: this is what avoids locking everyone out of the platform over a mistyped group.

TLS and the reverse proxy are up to you. Then set `ARCHIPEL_PUBLIC_URL` and `ARCHIPEL_TRUST_PROXY`, which takes the addresses of your proxies, never a count: without it, every client shares the rate limit and the audit only sees the proxy.

### Installing with Docker Compose

The delivery format is the same everywhere: Linux, or macOS with OrbStack or Docker Desktop. The machine only needs `compose.yaml` and a `.env` file, taken from this repository. The image is published on Docker Hub, for amd64 and arm64: `louischarnay/archipel:<version>`.

```bash
cp compose.env.example .env
```

In `.env`, fill in `ARCHIPEL_DATA_DIR`, an absolute path, and `ARCHIPEL_PUBLIC_URL`. The folder must exist. On Linux, it must belong to user 1000, and `DOCKER_SOCKET_GID` must be the output of `stat -c %g /var/run/docker.sock`. On macOS, keep it under your home folder, which is shared with the engine.

```bash
docker compose up -d
```

```bash
docker compose logs archipel
```

The logs give the code for the `/setup` wizard. The engine resolves paths on its side: that is why the data folder keeps the same path in the container and on the machine.

The Docker socket is worth root access to the engine: prefer a rootless engine, see [SECURITY.md](SECURITY.md).

Administration commands go through the container:

```bash
docker compose exec archipel node packages/server/dist/scripts/token.js create my-agent --days 90
```

```bash
docker compose exec archipel node packages/server/dist/scripts/audit-verify.js
```

```bash
docker compose exec archipel node packages/server/dist/scripts/rotate.js
```

### Updating and backing up

Change the version of `ARCHIPEL_IMAGE` in `.env`, then start again. Rolling back works the same way.

```bash
docker compose up -d
```

The platform tables are updated at startup, without deleting anything. Make a backup first.

A backup is a copy of the data folder, with the server stopped, here `~/archipel-data`. With a PostgreSQL database, back it up too:

```bash
docker compose stop
```

```bash
tar -czf archipel-$(date +%F).tgz -C "$HOME" archipel-data
```

```bash
docker compose start
```

To restore, put this folder back at the same path, with the same `ARCHIPEL_MASTER_KEY` if you use one: without it, the client secret and the database URL stay unreadable.

### Publishing a version

The version lives in `package.json`, shared by the root and every workspace. Each pull request bumps it, which CI checks: `minor` for a feature, `patch` for a fix. A `major` bump is a maintainer's decision.

```bash
npm run version:bump -- minor
```

Each merge to `main` runs the publish workflow: quick checks, then the image is built for amd64 and arm64 and pushed to Docker Hub under that version, `latest` moves to it, and the commit is tagged `v<version>`. A published number is never overwritten. `latest` is handy for a first try, but pin a version in `.env`: updating and rolling back then stay a change of tag that you decide. A merge without a bump, such as a Dependabot update, publishes nothing and ships with the next version.

The workflow signs in to Docker Hub with two repository secrets: `DOCKERHUB_USERNAME`, and `DOCKERHUB_TOKEN`, an access token with read and write rights.

Without `ARCHIPEL_IMAGE`, Compose builds the image from the repository: `docker compose up -d --build`.

### Configuring through the environment

For an automated deployment, copy `.env.example` to `.env`. Variables take precedence over the interface: a section set this way (`OIDC_ISSUER`, `DB_CLIENT`, `DB_URL`) shows as locked in **Settings**, and no setup code is asked for if OIDC is set there. The first administrator who signs in still sees the wizard.

| Variable | Role |
| --- | --- |
| `ARCHIPEL_PUBLIC_URL` | Public address, the only one accepted in `Host` and `Origin` |
| `ARCHIPEL_TRUST_PROXY` | Addresses or ranges of trusted reverse proxies |
| `ARCHIPEL_MASTER_KEY`, `ARCHIPEL_MASTER_KEY_FILE` | 32-byte key that encrypts the client secret and the database URL |
| `ARCHIPEL_SECRET`, `ARCHIPEL_SECRET_PREVIOUS` | Secret of at least 32 characters, otherwise generated in `data/secret` |
| `ARCHIPEL_SANDBOX_ENGINE` | `docker` or `podman`, detected by default |
| `ARCHIPEL_SANDBOX_RUNTIME` | Container runtime, for example `runsc` for gVisor |
| `ARCHIPEL_SANDBOX_MEMORY_MB`, `ARCHIPEL_SANDBOX_CPUS`, `ARCHIPEL_SANDBOX_PIDS` | Limits per app (128 MB by default) |
| `ARCHIPEL_RATE_LIMIT` | Requests per minute and per address (1200 by default, 0 to disable) |
| `ARCHIPEL_FETCH_MAX_MB` | Maximum size of a response read by `fetch` (5 MB by default) |
| `ARCHIPEL_TABLE_MAX_ROWS` | Maximum rows per app table (one million by default) |
| `ARCHIPEL_GIT_PROTOCOLS` | Clone protocols separated by `:`, `https` by default |

### Signing in

A session closes after one hour without activity and after eight hours at the latest. **Settings > Sessions** lists the open ones and lets you revoke one: the person is signed out at once, including from open apps.

Approving, putting back online, uninstalling, creating a token or changing the settings requires a sign-in less than 15 minutes old. After that, the interface sends you back to the provider.

### Getting unstuck

If the provider goes down or changes, run `npm run dev` on the server: **Continue locally** stays available next to it, and **Settings > Identity** lets you fix it. With Docker Compose, set `OIDC_ISSUER`, `OIDC_CLIENT_ID` and `OIDC_CLIENT_SECRET` in `.env` instead, then start again: the environment takes precedence over the saved configuration.

## Tables

The **Tables** page, reserved for administrators, lists every table of the live apps, without any data. Clicking a table shows the apps that reference it, with their access, then its columns, its database name, its permissions and its row count. Each table shows its domain:

- **Shared**: declared under `shared.*`, available to the apps that list it in their permissions.
- **Private**: reserved for its app.

**Exposed** flags a table listed in `exposes.data`.

## Activity

The **Activity** prompt, at the bottom of administrators' screens, follows the agent's submissions and the alerts: newly exposed data, changed permissions, rollback requests. Its badge counts unseen activities and alerts to handle. An alert stays there until **Seen** is clicked.

## External links

**Apps > Add an app > External link** puts a service that does not run on Archipel on the launchpad, with a name, an address and, if groups exist, an app group. It opens in a new tab.

The link appears at once for everyone signed in: no code is installed, so it does not go through review. Only an administrator adds or removes it, from the **Apps** page. The server fetches once the logo announced by the page, or `/favicon.ico`. If it cannot, for example for a local address, the launchpad shows the initial.

## Commands

The **Commands** button in the sidebar or `⌘K` (`Ctrl K` outside a Mac) opens a central search: app actions, apps, platform pages. It only offers what the signed-in account is allowed to do.

Actions come from `exposes.mcp` and apply to live apps. An action always requires clicking **Run**, even without fields, because it writes to the app. Each run is written to the audit log, without the content entered.

The shortcut does not answer when the focus is in an app opened in the launchpad: its isolated frame keeps the keyboard. The button stays available.

## Settings

Reserved for administrators.

- **Launchpad**: name, colour, logo, title, welcome and sign-in messages, background, app grouping, opening in the launchpad or in a new tab.
- **Identity**: OIDC provider, activated on the fly after a test sign-in.
- **Database**: SQLite or PostgreSQL. The connection is tested, the tables are created, then the platform restarts on its own.
- **Agents**: tokens for the CLI and the MCP server.

Switching databases does not copy data: apps, versions and tokens stay in the old one, intact, and you find them again by switching back.

These settings live in `data/instance.json`, readable only by the server's account, with the client secret and the connection URL. Back it up with the rest of `data/`.

## Version life cycle

Each submission (archive or Git link) goes through this pipeline:

1. **Manifest**: validation, with errors that give the field path, the received value, the expected value and the fix. The contract is published in `packages/manifest-schema/app.manifest.schema.json`, and the platform API in `GET /api/openapi.json`, reserved for administrators.
2. **Scan**: secrets, dynamic code, system access. A block stops everything: no code is run.
3. **Diff**: schema, permissions and exposed data compared with the live version.
4. **Preview**: the app runs on its own empty tables.
5. **Tests**: `health`, tests generated from the manifest, then `tests`.

The version then waits for a decision in **Review**: approve, request changes or reject. The comment is kept, and **Copy report** gives the agent a full JSON to iterate on.

Approving applies the migration and puts the version live on the fly. A permission change or a destructive change asks for an explicit confirmation; in the second case, a `bak_*` copy of the table is kept.

The **Review** badge counts the versions to handle. A collapsible prompt, at the bottom of administrators' screens, sums up the agent's activity: its latest submissions with their status, and its rollback requests. Both update on their own. The agent's reads (reports, logs, schemas) do not appear there.

A replaced version can be put back online from the app's page. Nothing is deleted: missing tables and columns are recreated empty, and lost data can be recovered from the `bak_*` copies.

## Driving it from an agent

The CLI and the MCP server submit a version and read its report, without the interface. They never decide: a version only goes live through a person, in **Review**.

### Connecting Claude Code

**Settings > Agents** gives the commands with your platform's address, and the token creation window repeats them. On the machine where Claude Code runs, with Node 22:

1. Install the Archipel skill. Run the same command again to update it.

   ```bash
   mkdir -p ~/.claude/skills && curl -fsSL https://apps.example.com/agent/skill.tar.gz | tar -xz -C ~/.claude/skills
   ```

2. Create a token in **Settings > Agents**, then connect the skill. The token is asked for without being displayed, checked, then saved in `~/.config/archipel/config.json` (0600), outside your projects.

   ```bash
   node ~/.claude/skills/archipel/scripts/archipel.mjs login https://apps.example.com
   ```

3. Ask Claude Code for an app, for example "Create an Archipel app to track equipment loans".

The skill teaches Claude Code the manifest, controllers, frontend and tests, the `validate`, `deploy --preview` and `report` loop, and how to read each report and each decision: the `decision_comment` of a change request is the instruction it will follow. It contains the CLI as a single file, without `npm install` or a cloned repository. Its sources are in `packages/cli/skill`, and `npm run build` assembles it in `packages/cli/dist/skill`.

`/agent/skill.tar.gz` downloads without a session: it contains no data and no secret. Claude Code asks for permission to run the CLI the first time; you can allow it for the session.

### Creating a token

The token is optional: without it, the platform works from the interface only. To create one, open **Settings > Agents** as an administrator, give it a name, a duration and, preferably, the apps it can submit. Without a list, it is valid for all apps, which the page flags. This is also where you see when it was last used and revoke it.

The token is shown only once: only its hash is kept. An agent token cannot create others.

Without access to the interface, the same thing is done on the server, with the same environment as the platform:

```bash
npm run token -- create claude --days 90
```

`npm run token -- list` and `npm run token -- revoke <id>` list and revoke tokens. The Docker image has no TypeScript loader: run `node packages/server/dist/scripts/token.js` there, and likewise `rotate.js` and `audit-verify.js`.

The CLI uses the connection saved by `login`. `ARCHIPEL_URL` and `ARCHIPEL_TOKEN` take precedence, together: useful in continuous integration, with a secrets manager.

```bash
export ARCHIPEL_URL=http://127.0.0.1:3000
export ARCHIPEL_TOKEN=arc_...
```

A token can submit an archive, read the reports and logs of the versions it submitted, read the schemas (tables and columns, no data) and report a rollback need. It gets a `403` on everything else, even with a session cookie in the same request.

### Commands

| Command | Effect |
| --- | --- |
| `archipel login <address>` | Checks the token, read from the keyboard without being displayed or from stdin, then saves the connection. |
| `archipel whoami` | Token in use, allowed apps and where the connection comes from. |
| `archipel logout` | Forgets the saved connection. |
| `archipel validate [folder]` | Validates the manifest, without a server or token. Taken routes and shared tables are checked at deployment. |
| `archipel types [folder] [--out file]` | Writes the TS types of `tables:` to `app.types.d.ts`, without a server or token. |
| `archipel openapi [folder]` | The app's OpenAPI contract, without a server or token. Online: `GET /api/apps/<id>/openapi.json`. |
| `archipel deploy [folder] --preview` | Validates, packs, submits, waits for the pipeline to finish and returns the report. `.git`, `node_modules` and `.env*` are not sent. |
| `archipel report <version>` | Full report, including `decision_comment`. |
| `archipel logs <version\|app> [--level error]` | A version's logs, or those of the latest version submitted for an app. |
| `archipel db:schema <app>` | Schema applied in the database and available `shared.*` tables. |
| `archipel promote <version> [--wait 600]` | Reports the review, or waits for the decision. Changes nothing. |
| `archipel rollback <app> [--to <version>] [--reason <text>]` | Asks for a rollback: the alert appears in **Activity**, and a person acts from the app's page. |

With the skill: `node ~/.claude/skills/archipel/scripts/archipel.mjs <command>`. From this repository: `npx archipel <command>`.

The result is always JSON on stdout, with a `next` field that says what to do next. `--preview` is implicit: no command puts anything live.

| Exit code | Meaning |
| --- | --- |
| 0 | Success: valid manifest, version ready for review, or version live for `promote` |
| 1 | Failure to read in the result: manifest, pipeline, rejected version |
| 2 | Usage, connection or permission error |
| 3 | Human decision pending |

An agent's loop:

```bash
npx archipel validate samples/customers
npx archipel deploy samples/customers --preview
npx archipel promote rel0123456789ab --wait 600
```

`samples/tickets` reads the shared table of `customers`: as long as `customers` is not live, its deployment fails with an error that says so. After a `changes_requested`, `decision_comment` holds the reviewer's request: fix and deploy again, the new submission replaces the one that was waiting.

### MCP server

`archipel mcp` exposes the same operations over stdio: `validate`, `generate_types`, `app_openapi`, `deploy_preview`, `get_report`, `logs`, `db_schema`, `promote`, `rollback`. It runs next to the agent, because it must read the app folder, and adds no service to the platform.

With the skill, Claude Code does not need it: it runs the CLI. For another agent, create a `.mcp.json` at the root of the project it works in, then restart the session and accept the server. After `login`, it contains no token:

```json
{
  "mcpServers": {
    "archipel": {
      "command": "/absolute/path/to/node",
      "args": ["/Users/you/.claude/skills/archipel/scripts/archipel.mjs", "mcp"]
    }
  }
}
```

`which node` gives the path to Node: a desktop app does not necessarily see your shell's. Paths must be absolute. If you pass `ARCHIPEL_URL` and `ARCHIPEL_TOKEN` in `env` instead, add this file to `.gitignore`.

## Writing an app

A full example of manifest, controllers and frontend: [samples/tickets](samples/tickets).

**Controller**: a module that exports a default function. It depends only on `ctx`.

```js
export default async function close(ctx) {
  const ticket = await ctx.db.table('ticket').get(ctx.params.id);
  if (!ticket) throw ctx.error(404, 'Ticket not found');
  return ctx.db.table('ticket').update(ticket.id, { status: 'done' });
}
```

| `ctx` | Role |
| --- | --- |
| `params`, `query`, `body`, `user` | The request and the user (`sub`, `name`, `roles`) |
| `db.table(name)` | `list`, `get`, `insert`, `update`, `remove` |
| `fetch` | Limited to `permissions.network`, response read in full and capped |
| `log` | `info`, `warn`, `error`, visible in the platform |
| `error(status, message)` | Error to throw to answer anything other than 200 |

No `npm install` is run: a controller has no external dependency.

**In TypeScript**: `@archipel/sdk` gives the type of `ctx`, and `archipel types` the type of the tables. The package only contains types: it is imported with `import type`, and a real import is refused by `validate`. Outside this repository, add it with `npm install -D file:<path>/packages/sdk typescript`. `samples/tickets` serves as an example:

```ts
import type { Controller } from '@archipel/sdk';
import type { Tables } from '../app.types.js';

const close: Controller<Tables, { id: string }> = async (ctx) => {
  const ticket = await ctx.db.table('ticket').get(ctx.params.id);
  if (!ticket) throw ctx.error(404, 'Ticket not found');
  return ctx.db.table('ticket').update(ticket.id, { status: 'done' });
};

export default close;
```

The manifest points to the compiled JavaScript (`handler: ./api/close.js`): compile with `tsc` before deploying. If the app has a `tsconfig.json`, `archipel validate` and `archipel deploy` run `tsc --noEmit`, and a type error blocks the submission.

A controller runs in a container without network: `ctx.fetch` goes through the host. There is no streaming and no `WebSocket`, and responses are capped at 5 MB. An entry of `permissions.network` takes one of these forms:

| Form | Allows |
| --- | --- |
| `api.example.com` | `https` on port 443, to a public address |
| `api.example.com:8443` | `https` on this port |
| `http://intranet.local:8080` | `http` and private addresses, with a warning in review |

Redirects are checked again, and the address is checked at connection time. The loopback and metadata addresses stay refused in every case. A preview, and its frontend, only reach the rules already approved for the app: a rule added by a version applies once a person approves it.

**Frontend**: static files. `window.archipel` is injected into each HTML page.

```js
const tickets = await archipel.api('/data/ticket');
await archipel.api('/data/ticket', { method: 'POST', body: { title: 'Out of order' } });
await archipel.api(`/tickets/${id}/close`, { method: 'POST' });
```

The API generated for a `crud: true` table is under `/data/<table>`: `GET`, `POST`, `GET /:id`, `PATCH /:id`, `DELETE /:id`. The list accepts `limit`, `offset` and a filter per column.

The frontend runs in an isolated origin, which has consequences worth knowing:

- no `localStorage` and no cookies: keep the state in a table;
- a single HTML page: prefer client-side routing;
- external domains (CDN, API) must be listed in `permissions.network`;
- the token lasts one hour: beyond that, the app must be reloaded.

**Action**: an entry of `exposes.mcp` appears in [the commands](#commands) and calls a declared controller, with the permissions of the person running it.

```yaml
exposes:
  mcp:
    - name: close_ticket
      description: Closes a ticket by its id
      calls: POST /tickets/:id/close
      input: { id: uuid }
```

`input` types: `uuid`, `string`, `integer`, `number`, `boolean`. All fields are required. Path fields go in the URL, the others in the body, or in the query for a `GET`. A path parameter missing from `input` is asked for as text.

## Tests

```bash
npm test
```

This command runs vitest on the packages (`packages/*/test`), then the integration suite in `test/` on SQLite. To replay the integration suite on PostgreSQL, with an account allowed to create databases:

```bash
ARCHIPEL_TEST_PG=postgres://archipel@127.0.0.1:5432/postgres npm test
```

To run the test apps in a container and attempt real attacks (Docker or Podman required):

```bash
ARCHIPEL_TEST_CONTAINER=1 npm test
```

## Known limits

- **Controller isolation**: the container is the boundary, and the process mode of `npm run dev` is not one. Details in [SECURITY.md](SECURITY.md).
- **Scan**: pattern matching, useful on generated code, and can be bypassed by code that tries to. It helps the reviewer, it does not protect.
- **Agent token**: with `npm run dev`, `/auth/login` opens a session for any local call: the guarantee only makes sense with OIDC.
- **Not delivered yet**: the launchpad assistant (`exposes.mcp` tools run from the commands, not yet through an LLM), LLM quotas (`permissions.llm` is shown, not enforced), exportable audit.
- **A single instance**: mounts are kept in memory.
- **Databases**: SQLite and PostgreSQL are tested. Another Knex driver remains possible through `DB_CLIENT` and `DB_URL`, without guarantees.
